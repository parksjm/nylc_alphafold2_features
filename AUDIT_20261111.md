Result of re-running the corrected pipeline on the 285 retained models and comparing with `legacy/nylc_all.merged_data_20250310.csv`
(`results/legacy_comparison_20261111.csv` is produced by the notebook): 94 of 121 columns are identical, and the rest are explained below.

## Robustness / reproducibility fixes (no change in values)
- Prep: cell "combine FASTA files" was a markdown cell (never ran); `!rm data/Nyl[0-9]*.fasta ...` deleted files inside `data/`; the MAFFT path (`seqs/`) was wrong and `string` was not imported; empty FASTA lines crashed the parser. The notebook no longer writes into `data/`.
- Skip-flag files (`POSTPROCESS_DONE`, `BSA_DONE`, `FPOCKET_DONE`, `PYMOL_SESSION_DONE`) skipped work whenever they existed, even for a different set of models. Replaced by output-exists checks (`NYLC_FORCE=1` to redo).
- Beta start was looked up by substring (`model_name in line`); the pTM/ipTM JSON was found by prefix glob (`nyl05*`). Both are now exact. The raw-model list is checked up front.
- `%%writefile` scripts moved to `scripts/`; processing runs in parallel; fpocket pocket selection uses text parsing of the STP records instead of PyMOL (Biopython would silently drop alpha spheres, because STP atom names repeat).
- Key-residue motifs are asserted to be residues 146/219/267/306 of NylC-GYAQ; the hard-coded `'>nylc-gyaq/1-355'` lookup is gone.
- The 24 extra picks (nyl096-nyl119) are removed from the MSA, sequences and activity table. Alignment columns were kept, so MSA-based features are unchanged.

## Remaining differences from legacy (expected)
- **Volume** (fpocket) differs for ~275 enzymes by a median of 1.4% (max 8%): fpocket estimates volume by Monte Carlo sampling. All other fpocket descriptors are identical.
- dp171: see #4.

## Observations not changed
- fpocket pocket choice (nearest alpha sphere to Thr OG1) is a heuristic and the descriptors are frame/conformation sensitive.
- Chain-matching RMSD windows (`resi 5-260`, `267-340`) are in 5y0m numbering and hard-coded.
- The PyMOL session notebook step (1.7 GB `.pse`) was dropped from the pipeline; add it back only if needed for visualization.
- `data/NylC_Build_Results.xlsx` has extra variants `nyl050b`/`nyl050c` and wild-type NylC; they are not in the MSA and are ignored.
- The `nylc_dp189/raw_af2_dp189` folder only has *unrelaxed* PDBs and no JSON files; the run used the relaxed models + JSON from `nylc_all/raw_af2_pdb_json`. Make sure the Zenodo upload for dp001-dp189 contains those files.
- The Zenodo dp95 archive is named `final_af2_dp95_zenodo.tgz` and holds processed models; older dp95 files used two-digit names (`nyl01`). The notebooks need raw relaxed models with three-digit names (`nyl001`).
